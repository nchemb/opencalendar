# v2 Playwright e2e checklist

`npx playwright test` — 34 tests, `desktop` + `mobile` projects, run green twice in a row (fresh production build each time).

1. **Free booking end to end** — `booking.spec.ts`: calendar → slot → form → `/success`; DB row `CONFIRMED` with `googleEventId`/`meetLink` set; booked instant disappears from a fresh visitor's picker.
2. **All question types + guests + non-Meet location; required enforcement; answers store with ids** — `booking.spec.ts`: `strategy-call` type has a required `long_text` + optional `short_text` question and two locations; submit is blocked by native `required` until the question is answered; switching to `phone_invitee` reveals and requires a phone field; guests stored deduped/lowercased; `booking.answers` equals `[{id,label,answer}]`.
3. **Multi-duration event type** — `booking.spec.ts`: `multi-duration` type, picking the 60 min radio books a 60-minute slot (asserted from `endTime - startTime`).
4. **Manage page: reschedule, cancel with reason, `/cancel` redirect, cutoff protection** — `manage.spec.ts`: reschedule moves `startTime` and sets `rescheduleCount` to 1, then cancelling the same booking with a reason sets `status CANCELLED` and stores the reason; `/cancel/<token>` redirects to `/booking/<token>?action=cancel`; the `cutoff-call` type (`cancelCutoffHours: 999999`) shows the policy message and renders no Reschedule/Cancel buttons.
5. **Single-use link** — `single-use-link.spec.ts`: a link seeded directly in the DB books once (`usedAt`/`bookingId` set), a second visit with the same `?link=` shows "already been used" instead of a calendar.
6. **Paused host** — `demo.spec.ts`: toggling `Host.paused` (reset in a `finally`) replaces the calendar with the paused message.
7. **Paid type with no payments configured** — `demo.spec.ts`: the e2e server runs with no Stripe key at all (the real-world state this exercises for a self-hoster who hasn't configured payments, and incidentally also the state demo mode forces); submitting shows "Payments are not configured on this instance." in the form, no booking is created.
8. **Embeds** — `embed.spec.ts`: inline embed via `data-bookkit-inline` mounts and auto-resizes; `theme`/`accent` reach the embed URL; popup opens/emits/closes on Escape; `BookKit.open()` prefill fills name/email and `bookkit:booked` fires as a window CustomEvent with the booking email; v1 `widget.js` (`data-bookkit`, `.bookkit-inline`) still mounts and books; bare iframe with no script works; embed page is `noindex`.
9. **Brand page + OG image** — `brand.spec.ts`: `/u/<brand>` lists active non-secret types and hides the secret one; unknown brand 404s; `opengraph-image` route returns `200 image/png`.
10. **Admin** — `admin.spec.ts`: login gate, wrong password rejected (UI + API), successful login shows Overview + system health, logout; create an event type through the editor (Name + Slug, rest defaulted) and it's immediately bookable; a public booking shows up in the Bookings list, its detail page renders the audit log (`confirmed` entry), cancelling from admin sets `CANCELLED` and adds a `cancelled` audit entry; Settings renders its sections; anonymous admin API POST is 401.
11. **Mobile** — `mobile.spec.ts` (`mobile` project, Pixel 7): free-booking flow and the manage (cancel) flow complete with `document.documentElement.scrollWidth <= innerWidth` at every step; the slot list never becomes its own inner scrollbox.

`screenshots.spec.ts` — kept working (selectors/copy updated for v2: `#bk-q-q1`, `data-bookkit-inline`, `.bk-inline-iframe`, `.bk-modal`, "Event types"/"New event type"). Opt-in via `SCREENSHOTS=1`, not part of the normal run.
